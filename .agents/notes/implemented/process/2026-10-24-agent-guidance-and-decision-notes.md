# Agent Note: 长期规则、运行合同和决策理由分别维护

Status: implemented — 所有者授权 #150，当前未提交文档调整落实本次职责分工

## Problem

AGENTS 逐渐混入功能参数、漏洞版本和已完成事项，普通实现更新也牵动长期指令；重要理由却只在本地证据与对话中，下一次会话难以复用。既有 notes 契约有格式校验，缺失笔记本身不会让代码 CI 失败，不能据 CI 绿推断收尾完成。

## Decision

- AGENTS 保留权限、安全、架构、验证入口和交付约定；每次 PR 核对影响，实际受影响才修改。
- 运行机制和参数归对应 docs；理由与放弃项归 notes；当前状态归 GitHub；本轮原始证据归本地 .vidt。
- 收尾给出新建、更新已有 owning note、或无长期结论的处理结果。已有权威文档使用薄指针，普通机械改动无需新笔记。
- 修正旧笔记目录分类时保留原内容；历史叙述中的路径与状态不当作当前运行指令重新解释。

## Alternatives considered

- 每个 commit 必须新增一篇 note：否决，制造重复与低价值记录。
- 把所有功能经验继续追加 AGENTS：否决，读入成本与失效面随实现细节增长。
- 把 .vidt 报告直接当长期结论提交：否决，它们包含瞬时状态和证据边界，不能代替可复用的决策理由。
- 给全部历史笔记套用 AGENTS 的当前路径检查：否决，历史理由允许记载当时状态；使用 notes 的目录、Status 和链接契约校验。

## Consequences

文档数量不是完成标准；需要检查职责是否唯一、理由是否可检索及引用是否有效。目录校验通过也不能证明所有应写决策已经覆盖，收尾仍需做一次明确判断。
本次收敛不改变业务行为、已有权限审批、#140 验证条件或生产操作授权。后续若改变职责边界，另开决策并交叉链接，不覆写旧决策。
