# 监控大盘的后台归属与前后台跳转

Status: implemented — 大盘由统一后台壳承载，返回前台提供预取和加载反馈

## 问题

侧边栏中的监控大盘使用原生链接跳到后端独立 HTML，丢失后台导航、面包屑和返回前台入口。返回前台则通过 router.push 等待动态首页服务端取数，既没有预取，也没有点击后的反馈。

## 决定

- 导航与面包屑统一使用 `/admin/dashboard`。前端旧 `/dashboard` 临时重定向到这个入口。
- 后台页内嵌同源 `/api/v1/metrics/dashboard` 画布。它与原 `/dashboard` 使用同一份 HTML、图表脚本和管理员鉴权，只把独立侧栏改为内容区页签，隐藏重复品牌、系统导航和页面标题。
- 数据判定和图表口径继续由[大盘改版合同](2026-11-02-monitoring-dashboard-rework.md)维护。Next 不复制阈值与监控业务逻辑。
- 嵌入画布有加载、失败、15秒超时及重试状态；HTTP错误页不能被当作画布成功。iframe文档卸载时终止旧画布轮询。
- 返回前台使用 Next Link 完整预取；useLinkStatus 提供等待反馈，路由 loading 边界让服务端首页尚未返回时也能及时显示前台壳与骨架。后台数据速度仍取决于服务端，不以本地跳转替代生产性能证明。

## 替代方案与代价

没有原样嵌入完整独立页面：会产生双侧栏。也没有重写 React 监控面板：会复制 Canvas、阈值和轮询逻辑。嵌入模式只改宿主布局，保持单一数据口径。

iframe 有独立滚动区域；服务端和前端需同版部署，旧后端没有嵌入端点时页面显式报错。后端原 `/dashboard` 保留以兼容直接后端访问，前端用户入口统一重定向。此变更不更改管理员权限、数据库结构和监控采集协议。

## 验证

导航清单、返回链接及等待反馈有前端测试；嵌入HTML与原脚本一致性、管理员依赖及匿名/普通用户/管理员访问有后端测试。后端 pytest 使用一次性 PostgreSQL入口；本地预览只启动当前大盘路由，其余GET/HEAD转发现有开发后端，不启动采集任务。真实生产跳转耗时和部署状态不由这些验证推断。
