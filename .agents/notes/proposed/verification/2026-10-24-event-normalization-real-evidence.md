# Agent Note: 事件归并的工程交付与真实效果分开验收

Status: proposed — 记录真实验证的依据与后续验收条件；当前进展以 #140 为准

## Problem

归并会影响文章是否独立展示。合成回归、临时代表池、模型建议或本地性能通过，都不能证明真实内容不会误归并；把工程合并当效果验收会掩盖样本来源和未知标签。

## Decision

采用独立的真实样本验证与有界试点路径。参数、启用步骤和停止条件的权威在
[docs/content-event-coverage.md](../../../../docs/content-event-coverage.md)，当前进展和决定在
[#140](https://github.com/fxbin/TopicEye/issues/140)。本篇是薄指针，不复制门槛或维护另一份 HOLD 状态。

## Alternatives considered

- 用 CI 绿替代准确率、人工留出或生产回读：否决，证据对象不同。
- 用 bootstrap 池补充实际 canonical 池数量，或把 unknown 自动建议算正确样本：否决，来源和标签都未经独立确认。
- 为交付开启生产 write，再靠误归并告警补救：否决，先满足真实验证与准确候选审批边界。

## Consequences

工程可以完成并合并，真实验证仍可能不足。后续真实调用、人工标注与试点不能由本笔记授权；需按权威文档和当次审批执行。
复核结论必须绑定准确候选，旧候选的真实模型冒烟不能提升为新候选验收。
本篇可在真实验证决策落地后按生命周期更新；不据 GitHub 单次状态变化覆写原取舍。
