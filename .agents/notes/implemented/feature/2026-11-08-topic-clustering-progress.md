# Agent Note: 增量话题聚类按扫描位置轮转

Status: implemented — 增量扫描位置按窗口持续保存，回归覆盖独立文章积压、跨会话续扫和回绕

## Problem

只取最早的 max_items 条未分组文章不能保证增量推进：独立文章会一直保持 topic_id 为空，足够多的独立文章可占满每轮候选，后续积压永远读不到。

## Decision

保持每轮 max_items 上限和 id 升序，使用既有 AppSetting 的 `topic_clustering_scan_cursor_v1:<days>d` 保存已完成扫描的位置。候选包含公共、已分析、窗口内且未分组的文章；独立文章也推进位置。走到末尾后从头复查，避免旧文章的标签/分析更新后永久失去机会。

扫描位置在本轮写入完成后与最后一批一起提交，现有分批提交继续保留。正常 API 和定时入口沿用同一任务租约；不通过重置全部关系推动进度，不覆盖已经分组的文章。它是扫描进度，不代表该位置以前的文章都已成组或通过质量判断。

## Alternatives considered

- 每轮从最早未分组文章重试：不采用，会被长期独立文章阻塞。
- 只扫最新文章：不采用，可能永久遗漏旧积压。
- 把每条独立文章都建成一个假话题：不采用，会混淆真实聚类含义。

## Consequences

新增进度配置行，无 schema 迁移。按窗口区分位置，改变窗口不会借用另一窗口的进度。仍是有界批次内聚类，不承诺跨批次全文全局聚类或真实选题效果。共享话题的公共范围沿用[数据归属合同](../architecture/2026-10-24-data-ownership-and-legacy-adr.md)。

回退代码时旧版本会忽略此配置行；无需删除话题或进度数据。生产执行与真实聚类效果需分别验证，本地回归不等于已运行生产任务。
