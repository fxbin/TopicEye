# 工作台页面的稳定布局与共享 UI

Status: implemented — 工作台统一页面锚点与指标卡，阅读场景保留独立版式

## 问题

页面虽然复用了 Panel，仍各自选择外壳宽度、主标题容器和指标卡实现。后台五档宽度会让标题在切页时移动；把主标题包入卡片还会增加一层留白。只检查溢出或 Panel 是否写 padding，不能防止这种跨页面样式断层。

## 决定

- 后台页面统一使用 `AdminPageShell` 的 1200px 内容上限，主标题置于外壳顶层。宽表格在自身区域横向滚动，表单阅读宽度由内部区域限制，不能通过改变页面壳宽度实现。
- 前台工作台的滚动、边距与内容宽度由 `globals.css` 的 `workspace-scroll` 维护，主标题使用 `page-title`。页面壳负责页面级留白；区块只管自身内容。
- 指标卡统一从 `components/StatTile.tsx` 导入；普通区块使用共享 Surface。统计数值采用等宽数字，说明可换行，不以截断掩盖拥挤。
- 后台原生表格的表头和单元格密度由 `.admin-workspace` 下的公共规则维护，复杂选择与操作行为仍由原页面负责。

## 未采用的方案

没有给基础 Panel 一律补默认 padding：满幅表格、列表和弹窗已有自己的内部分区，这会叠加留白。也不把日报、周报、月报、阅读器、登录与授权页强制改成工作台：它们的内容层级与主任务不同。

## 代价和边界

统一页面外壳后，宽屏表格可见宽度减少，应使用内部滚动；不能为了容纳宽表格重新给页面添加私有宽度。页面功能差异仍可影响内容高度和分栏，不要求所有屏幕拥有相同构图。此规则不改变 API、权限、数据持久化或模型行为。

`workspace-contract.test.tsx` 防止私有后台壳宽度、重复指标卡和嵌套主标题再次出现；`admin-surface-contract.test.ts` 检查 Panel 的显式留白选择。静态门禁不能替代真实截图和交互复核。

## 验证边界

本地页面检查与生产验收分开。批量截图可能触发 `/auth/me` 访问限流；缓存一次已验证会话身份只能用于布局复核，不能作为认证、权限或真实业务集成通过的证据。运行截图和本轮覆盖清单留在 `.vidt/`，任务状态以 GitHub 为准。
