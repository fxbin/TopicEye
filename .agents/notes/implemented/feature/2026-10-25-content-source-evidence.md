# 纯链接内容的原文证据准入

Status: implemented

## 为什么需要这个边界

AIHOT 的 RSS 条目曾只有 URL 标题和“阅读原文 via AIHOT”的跳转提示，却获得模型高分。仅修正卡片标题会留下错误精选；仅在采集时过滤则挡不住已经分析的历史条目。缺陷及交付状态见 [#153](https://github.com/fxbin/TopicEye/issues/153)。

## 维护入口

`backend/app/services/content_evidence.py` 维护捕获字段的可读性与标题恢复规则。证据只来自 `ContentItem.title`、原始摘要和正文；AI 摘要、推荐理由和分数不能为其自身提供证据。

- 去掉 HTML、链接和独立跳转标签后没有可读文本的条目，采集时保留原始记录并标记 `skip_analysis`、`no_readable_content`，不进入分类模型。
- 旧待分析条目在工作者入口重新核对，通过当前 fencing token 将其标为跳过并释放租约，不进入失败重试。直接分析入口也执行同一检查；手动分析 HTTP 入口在读取旧分析之前验证原文，缺失时明确返回 422，不把跳过误报为仍在分析。
- 今日精选在选择事件展示代表之前过滤无原文证据条目；评分适配器将证据结论传入统一引擎，在百分位和多样性计算之前排除。日报背景材料同样不能用旧 AI 描述填补空原文。
- URL 标题有实际摘要或正文时，使用原文第一句的有界摘录作为可读标题；没有文本时读模型显示“原文待补全”。采集的内容哈希仍由原始标题与 URL 计算，标题恢复不改变去重身份。
- DuckDB 精选与周期摘要查询保留原始正文证据，周期摘要使用独立的 `source_summary`，不能误将 AI 摘要当作 RSS 摘要。新话题聚类在分组与模型命名前排除无证据条目，不能恢复其旧分数；手动增强和相关上下文也须核对原文。正文不因此增加到公开精选响应。精选缓存命名空间同时升级，旧的序列化高分卡片不能绕过新的准入读取。

新趋势计算使用 `trend-v4`，话题与关键词快照都从 repository 读取捕获字段后筛选；当前精选统计也在事件选择和评分前核对原文。无证据的事件 canonical 可由可读的已接受成员代表，事件身份不改写。没有原文字段的旧只读分析快照保留兼容数字口径，不宣称已验证原文；正常生产 schema 必须携带标题、摘要和正文投影。

## 有意保留的范围

这是一道结构准入，不是内容真实性或模型评分校准证明。正常可读短标题仍可以携带有效信息，不要求每个信源都有全文。调用方自行提供评分维度的 HTTP/MCP 评分接口保持原有合同，不强制额外提供正文。

不新增网页抓取、模型生成标题、自动补全任务、迁移或历史回填；已有持久化日报、周期摘要、趋势快照与分析记录不改写。部署与生产数据修复各自需要实际运行证据。本地回归不能替代生产验收。

## 回归入口

`backend/tests/test_url_only_content.py` 用生产数据形状验证采集、直接分析、队列跳过与 fencing、历史高分精选、正常短标题、正文标题恢复，以及一次性 PostgreSQL 的精选、日报、增强候选和评分适配。`test_duckdb_service.py` 验证原文正文穿过真实 DuckDB 查询而未被 AI 摘要替代。测试仍须遵守 AGENTS 的一次性数据库入口。

下游贯通回归见 `backend/tests/test_url_only_downstream.py`：聚类与增强模型调用、旧增强缓存、相关上下文、新趋势话题/关键词成员以及无原文 canonical 的替代代表。真实 DuckDB 统计回归同时覆盖保留旧只读 schema 与使用当前原文证据两种路径。
