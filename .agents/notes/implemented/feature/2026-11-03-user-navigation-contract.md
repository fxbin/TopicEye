# 前台操作目的地与反馈边界

Status: implemented — 前台用户动作保持在可访问、语义相符的流程中

## 原因

后台页面从历史顶层路由迁入 `/admin/*` 时，`/feedback` 也被重定向到后台。前台更新记录中的个人反馈历史和收藏信源链接又复用了后台入口，普通用户点击后会被权限守卫退回，管理员则容易把后台管理误当成用户提交反馈的流程。仅测试路由权限不足以发现这些入口的目的地错误。

## 决定

- `/feedback` 是需要登录的前台反馈页面，承担提交、个人历史分页和查看处理回复；只调用 `createIssue` 与 `/product-feedback/issues/mine`。后台 `/admin/feedback` 负责处理所有人的反馈，前台不提供通向该工作台的用户动作。
- 更新记录中的“反馈建议”和用户导航统一进入 `/feedback`。取消旧 `/feedback` 到后台的永久重定向，移除原反馈弹窗及其“到后台看完整历史”的提示，保持一处用户提交与历史读取入口。
- 公共文章的来源标注不等于用户的私有信源。只知道来源名称时展示名称与类型，不能跳到 `/sources/me` 假装存在该来源详情；收藏的来源保留已有原文 URL，不带用户进入后台或无关的私有信源列表。未来若新增公共来源详情，需使用明确身份和可见性合同。
- 登录守卫和需要登录的操作保留原页面与查询条件。已登录但权限不足或模块关闭时返回前台，不把有效登录态当作“需要重新登录”。后台壳和个人中心的登录等待路径也使用同一回跳构造函数；OAuth 失败重试通过登录 URL 保留原目标，不丢失此前反馈或授权任务。
- 回跳地址必须是站内路径，拒绝协议相对地址、反斜杠、C0/DEL 控制字符，并按固定站点基准解析验证 origin；避免浏览器删除换行、制表符后把输入转成站外地址。
- 小说模块关闭时，已有小说收藏不显示无法访问的榜单入口。缺少有效 HTTP(S) 原文 URL 的榜单条目展示文字，不用 `#` 跳到页顶或打开当前页。

精选、话题线索与热词的前台入口已收敛，具体URL与兼容边界见[入口合同](2026-11-07-picks-materials-entry.md)。

## 保留边界

显式的“管理后台”“管理更新”入口仍仅管理员可见。历史管理路由 `/sources`、`/model-eval`、`/contents`、`/mother-topics/config` 和 `/stats/jobs` 的重定向是管理路由迁移，不是前台功能入口；本轮未凭路径外观删除它们。

数据库中的个人归属由后端 `/issues/mine` 保证，前端页面不能代替服务端权限检查。匿名用户在登录后回到反馈页；本轮没有改变后端匿名提交接口、数据库 schema 或后台处理权限。

## 回归入口与验证边界

- `user-entry-links.test.tsx` 锁住反馈重定向、收藏信源、模块关闭时的榜单入口及内容详情身份。
- `navigation.test.ts` 验证角色、功能开关、登录回跳和控制字符输入；反馈页面、来源标注与原文链接组件各自有回归。
- 浏览器验证用户提交流程、草稿保留、历史错误重试/翻页、处理回复、权限跳转和窄屏布局。隔离 fixture 的提交只证明前端交互及请求合同，不等于生产反馈交付或跨账号权限实测。
